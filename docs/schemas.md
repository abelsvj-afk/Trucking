# Data Schemas

Phase 6 deliverable per `MASTER AI ENGINEERING & SYSTEM DEVELOPMENT WORKFLOW`. This is a contract: once implementation starts, code conforms to this, not the other way around. Covers the MVP entities from `docs/requirements.md`, built on the relational, `company_id`-scoped approach decided in `docs/architecture.md`.

## Global conventions (apply to every table below)

- **Primary key:** `id`, UUID, generated by the database.
- **Tenant scoping:** every table has a `company_id` (UUID, references `companies.id`, not null). Row-level security restricts every query to the caller's own `company_id` — this is the architectural decision from `docs/architecture.md`, applied concretely.
- **Timestamps:** every table has `created_at` and `updated_at` (both `timestamptz`, defaulting to now, `updated_at` maintained on write).
- **Soft delete:** every table has a nullable `deleted_at` (`timestamptz`). Deleting a record sets this instead of removing the row — per the workflow doc's "reversible actions beat irreversible actions" principle and the reliability requirement in `docs/requirements.md` that data must never be silently lost. Deleted records are excluded from normal reads but never physically erased. (No user asked for a stricter "no permanent deletes" rule in `docs/governance.md` — this is the ordinary engineering default for financial data, not an extra restriction.)
- **Money:** stored as integer cents (not floating point), to avoid rounding errors in financial figures.

## Financial summary

Not a stored table. It's computed on read from `loads` (status `confirmed`/`completed`) and `expenses`/`fuel_purchases`/`maintenance_events` within a date range — see `docs/api-contracts.md`'s `/financial-summary` endpoint. No dedicated table exists yet because there's no real performance reason for one (matches the "no caching yet" decision in `docs/architecture.md`) — revisit only if computing it live actually becomes slow.

---

*Column-level detail beyond what's needed to satisfy `docs/requirements.md`'s MVP scope is deliberately not included — e.g. no `documents` versioning, no `loads` rate-negotiation history. Add fields here, not silently in code, when a real need shows up.*
